2. Especificación
-----------------

**Declaración:**

   El sistema DEBE permitir modificar restricciones SoD existentes
   CUANDO el admin necesita ajustar severidad o descripción.

**Descripción:**

   Campos modificables:
   
   - Severidad (HARD ↔ SOFT)
   - Descripción/Motivo
   - Estado (Activa/Inactiva)
   
   **Campos NO Modificables:**
   
   - Funciones involucradas (A y B)
   - Para cambiar funciones: eliminar y crear nueva
   
   **Cambio de Severidad:**
   
   - SOFT → HARD: Requiere validar conflictos existentes
   - HARD → SOFT: Permite sin validación adicional

----

3. Criterio de Aceptación
-------------------------

::

   DADO admin editando restricción SoD
   CUANDO modifica campos permitidos
   ENTONCES se actualiza el registro
   
   Escenario 1: Cambiar descripción
   DADO restricción existente
   CUANDO se modifica la descripción
   ENTONCES se actualiza sin validaciones adicionales
   
   Escenario 2: SOFT a HARD
   DADO restricción con severidad SOFT
   CUANDO se cambia a HARD
   ENTONCES se validan conflictos existentes (FR-043.02)
   Y si hay conflictos, se requiere resolución
   
   Escenario 3: HARD a SOFT
   DADO restricción HARD sin conflictos
   CUANDO se cambia a SOFT
   ENTONCES se actualiza directamente
   
   Escenario 4: Desactivar restricción
   DADO restricción activa
   CUANDO se cambia estado a Inactiva
   ENTONCES la restricción no se valida en asignaciones
   Y se mantiene para histórico
