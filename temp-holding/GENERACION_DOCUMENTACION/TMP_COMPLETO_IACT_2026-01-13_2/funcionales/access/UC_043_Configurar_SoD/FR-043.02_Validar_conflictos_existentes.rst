2. Especificación
-----------------

**Declaración:**

   El sistema DEBE identificar usuarios que ya tienen asignadas las
   funciones en conflicto CUANDO se crea una nueva restricción SoD.

**Descripción:**

   Proceso de validación:
   
   1. Obtiene funciones A y B de la restricción
   2. Busca usuarios que tengan AMBAS funciones asignadas
   3. Genera lista de usuarios afectados
   4. Presenta al admin para resolución antes de activar
   
   **Opciones de Resolución:**
   
   - Revocar función A de usuarios afectados
   - Revocar función B de usuarios afectados
   - Cancelar creación de restricción
   - Crear restricción como SOFT (solo advertencia)

----

3. Criterio de Aceptación
-------------------------

::

   DADO nueva restricción SoD en proceso de creación
   CUANDO existen usuarios con las funciones en conflicto
   ENTONCES se muestran y se requiere resolución
   
   Escenario 1: Sin conflictos existentes
   DADO restricción ACC-001/ACC-005
   CUANDO ningún usuario tiene ambas
   ENTONCES validación pasa directamente
   Y se permite crear la restricción
   
   Escenario 2: Con conflictos existentes
   DADO 3 usuarios con ambas funciones
   CUANDO se valida la restricción
   ENTONCES se muestra lista de los 3 usuarios
   Y se presentan opciones de resolución
   
   Escenario 3: Resolución por revocación
   DADO usuarios en conflicto mostrados
   CUANDO admin elige "Revocar función A"
   ENTONCES se revoca ACC-001 de todos los afectados
   Y luego se crea la restricción
   
   Escenario 4: Resolución como SOFT
   DADO usuarios en conflicto
   CUANDO admin elige "Crear como advertencia"
   ENTONCES se crea restricción con severity = SOFT
   Y usuarios actuales mantienen ambas funciones

----

4. Reglas y Restricciones

necesarias para operar.
